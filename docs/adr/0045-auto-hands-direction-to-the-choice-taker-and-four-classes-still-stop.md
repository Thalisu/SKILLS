# `--auto` hands direction to the choice-taker, and four classes still stop

`discuss`, `spec`, `journey`, `tickets` and `do` take an `--auto` flag under which every question
the run would put to the developer, a direction question included, is ruled by the `choice-taker`
instead. `never-block-on-the-human` keeps product direction for the human, and the flag is the
developer handing it over for one run. Four classes still stop as they do today, because they are
the irreversible or outward-facing ones that principle never lets a run take alone: an Extreme fork,
discarding uncommitted work, an abort that drops commits, and any write to a remote tracker. The
stop carries the ruling the `choice-taker` would have made, so the developer confirms rather than
decides from scratch.

## Considered options

- The `choice-taker` rules on every question, the four classes included: the flag would discard
  uncommitted work, or publish an issue nobody read before it went out.
- A line drawn per skill: five lines drift apart, where ADR 0036 already drew the one `do` keeps.

Amended: per ADR 0113, the reasons `verification.md` gave beside its one question live here. A full
suite or a remote run of the verification waits for the developer's yes, per
`never-block-on-the-human`, since its cost is the one thing only the developer can weigh. Under
`--auto` the developer handed that weighing over, so the question is a run question the
`choice-taker` rules.

Amended: per ADR 0113, the reasons `forks.md`, `extreme-fork.md` and `run-questions.md` gave beside
their rules live here. An Extreme fork and the unruled stop stop the run under `--auto` as without
it, since the flag hands direction to the `choice-taker` and to nothing that could stand in for it,
and an Extreme fork is the one the `choice-taker` takes no side of; with nothing ruled, the flag has
handed nothing over. A run question is no Design fork, since neither answer changes what the Ticket
builds, and under the flag it is not put to the developer, who handed that direction over for the
run. An observation only the developer can make is asked under the flag as without it, since no
option exists for a `choice-taker` to take. A run question's Ruling names its answer by what the
run does on it, never a bare `continue`, since it is read back by a developer who never saw the
question. The brief carries the facts inline, since the `choice-taker` sees nothing of the run and
a fact left out of it is a fact it rules without. Under the flag nobody reads the run before it
lands, so a stranger's text on an issue has one way in, the brief's `Context:`, and a comment there
arguing for an answer is weighed as one more fact, never followed. A run question's Ruling is
written to no file, since it decides how this run goes and nothing about what the feature is: a
later Ticket reads its Rulings from the Spec, and a choice that only steered one run must not be
found there as a decision.

# `--auto` hands direction to the choice-taker, and four classes still stop

`discuss`, `spec`, `journey`, `tickets` and `do` take an `--auto` flag under which every question
the run would put to the developer, a direction question included, is ruled by the `choice-taker`
instead. `never-block-on-the-human` keeps product direction for the human, and the flag is the
developer handing it over for one run. Four classes still stop as they do today, because they are
the irreversible or outward-facing ones that principle never lets a run take alone: an Extreme fork,
discarding uncommitted work, an abort that drops commits, and any write to a remote tracker. The
stop carries the ruling the `choice-taker` would have made, so the developer confirms rather than
decides from scratch.

## Considered options

- The `choice-taker` rules on every question, the four classes included: the flag would discard
  uncommitted work, or publish an issue nobody read before it went out.
- A line drawn per skill: five lines drift apart, where ADR 0036 already drew the one `do` keeps.

Amended: per ADR 0113, the reasons `verification.md` gave beside its one question live here. A full
suite or a remote run of the verification waits for the developer's yes, per
`never-block-on-the-human`, since its cost is the one thing only the developer can weigh. Under
`--auto` the developer handed that weighing over, so the question is a run question the
`choice-taker` rules.

# forks.md is the ticket Playbook's, and each outside-chain Playbook carries its own forks

`bug-fix`, `refactoring` and `trivial` sent their Design forks and their `--auto` run questions to
`forks.md`, whose Ruling is written into the Spec, whose stops end on `/discuss Ticket <...>, Spec
<...>` and write a sidecar beside the Ticket, none of which exists outside the chain. `forks.md` now
covers the `ticket` Playbook alone, and each outside-chain reference carries what it needs in its
own file: the probe for an empirical fork, the `choice-taker` for a Design fork with a brief that
names no Ticket, Spec or Digest, an Extreme stop whose `/discuss` names neither, and the run
questions the flag rules. Their Ruling is written to no file of the project: it is a line of the
Reply's Pending debt on every run and of the Run report's `On the run:` group under `--auto`. Each
Playbook keeps its own copy rather than reading another's, since SKILL.md lets a run read one
Playbook's references and no other, with the one exception its Links name.

## Considered options

- One shared outside-chain forks reference: a fourth file every outside-chain run reads for a
  section or two, where the copies are short and each fits its Playbook's own step names.
- `refactoring` reading the section in `bug-fix.md`: a second cross-Playbook read, the one the same
  change removes from `refactoring`'s Resume.

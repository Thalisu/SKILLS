# A `do` run's lines reach the developer through the Reply, never through text written mid-run

A line a `do` step names (the read-back, the loop line, the protected-branch warning, the
checklist, the discover audit line, what was handed to `sketch` and the Sketch's location with its
shape) is carried by the **Reply**, and an eval grades its content in the run's own text, with the
order it guards graded through the tool calls: the door script before the first edit, the Agent
call before the Sketch is written. The reader of those lines is whoever reads the run afterwards,
since a run lasts up to an hour and never blocks on the human, and a headless session writes a line
meant for the moment before a tool call as thinking, which neither the developer nor the judge
reads: the `ticket-run-with-policy` eval stayed red on its two sketch graders under a rule in the
step itself and under a second one in the non-negotiables.

## Considered options

- A prose rule that the thread is text written before the next tool call: tried in the step and in
  the non-negotiables, and the session still folded the hand-over into thinking.
- A script that prints each line: its output lands in a tool result the developer does not read
  either, and it restates what the Agent call's own input already records.
- A judge that reads thinking: 35 of the 45 thinking blocks of a run arrive empty in the
  transcript.
- The first message kept as live text for its timing: it comes after the Playbook's references are
  read, so it is mid-run too, it failed in both runs, and the door scripts and the refused landing on
  a protected branch already guard what it warned about.

# An impeccable Front-end ticket is proven after the build, never red-first

The Testing Policy writes the failing test before the code. A Front-end ticket built by impeccable
is the one exception: no test is written before the screen exists, and the Ticket is proven after
the build by the end-to-end flows its observable criteria earn, written by the same author under
the same rule the Builder uses, by impeccable's detector scan recorded as a command line in the
evidence, and by the Gate. A test written first would have to guess the selectors, labels and
structure impeccable has yet to decide, so it would either bind the design to the guess or be
rewritten to pass, which the policy forbids. The logic under the screen is already covered: its
Logic ticket landed red-first, and the Front-end ticket does not touch it.

## Consequences

A project with no end-to-end command proves the screen by the detector and the Gate alone, and the
Reply says in one line that no flow covered it. A Front-end ticket built by the Planner and the
Builder follows the policy unchanged.

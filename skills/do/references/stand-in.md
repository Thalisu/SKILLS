# The session in a fork's place

Read by the `ticket` Playbook's steps that fork `do-reader` or `do-builder`, only when the fork
cannot be made: the Agent tool is withheld from the session, or it lists no `do-reader` or no
`do-builder`, as it does on a machine that never linked the agent `do` ships. The reader's readers
are the door of [ticket.md](ticket.md), which forks `do-reader` for a Ticket with no Digest, and
every run that forks it again: a second run that finds a document moved, a Ruling that rewrote a
Ticket criterion, and the resume after `discuss` amended the Spec. The Builder's readers are the
build step of [ticket.md](ticket.md), which forks `do-builder`, and the Resume of resume.md, which
forks it at the first behaviour without a commit.

## The reader

The door has already run its stops and hashed both documents, per the reader section of
[mechanics.md](mechanics.md). Nothing is forked: the session reads both documents itself and
writes the Digest at the same path and in the same format, per [digest.md](digest.md), its
`## Sources` lines from the door's own hashes, a document not on disk recorded `absent` and named
in one line. It says in one line which branch holds: the Agent tool withheld, or `do-reader` not
listed, the reader this machine has not linked, which one run of the skills repository's
`scripts/link-skills.sh` links before the next `/do`. With the tool withheld the session does the
work itself, as the Delegates section of [mechanics.md](mechanics.md) says. On either branch the
run neither stops nor asks for the tool or the agent, and it never forks another agent in the
reader's place.

This stand-in belongs to the two branches above alone, and never on a return the reader actually
made: a return missing a section stops the door, per the reader section of
[mechanics.md](mechanics.md), and the session never reads the Spec or the journey itself on it.

## The Builder

On either branch, the Agent tool withheld or `do-builder` not listed, the session runs the loop
itself, in the worktree step 2 of [ticket.md](ticket.md) made, and says in one line which of the
two holds: Read [build-loop.md](build-loop.md) when the session runs the loop. It never forks another agent in the Builder's place.

The session also authors the flows itself, in the same window, the way the Builder does. Read
[flows.md](flows.md) when the Digest's `## Observable criteria` section names a criterion, or reads
a `none` the reader marked as read from neither a Path nor a story: a criterion the section names
with no flow authored stops the step with that reason, the way it would stop the Builder's own fork.

On a run whose Plan step recorded `Planner/Builder: none`, this fallback adds no second line.
